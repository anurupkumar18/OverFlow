# Overflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Build a polished, truthful conference planner with resilient search and useful Plan B options.
**Architecture:** One Node service, Elasticsearch when configured, verified local catalog for read-only fallback. Browser modules and local personal bookmarks.
**Tech Stack:** Node 22+, native HTTP/fetch, vanilla JS/CSS, Node test runner, Python ingestion/evaluation, Playwright CLI.
**Spec:** docs/superpowers/specs/2026-11-08-overflow-design.md

## Global Constraints
- No LLM in request path; one stateless service; Elasticsearch only server datastore.
- Every search and Plan B response contains mode and degraded; unknown crowd signals are not zero.
- UTC API dates end with Z; display/day filtering America/Denver.
- Plan B: at most 3; +/-10 minute start; different room; not ended; not likely full; same-floor first when known.
- No credentials in client, source, output or logs. No fabricated labels, stats, findings or deployment status.
- Browser API requests only in app/public/js/api.js. Keyboard navigation, visible focus, 44px controls and responsive layout.

## Review Focus
- Unavailable cloud providers: snapshot renders and labels limitations; protected writes return 503.
- UTC date boundaries / host timezone drift: Denver filter correct under 3 TZs.
- Invalid IDs, oversized bodies and HTML-like content: 4xx responses and escaped UI.
- Empty filters / saved talks not in current results: useful empty state and persistent itinerary.
- Rapid typing / dialog focus / narrow screens: newest result wins, focus restored, no overflow.
